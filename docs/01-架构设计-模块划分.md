# 电商经营数据智能问答系统 —— 整体架构与模块划分

> 基于 data-agent-tutorial（Java Spring Boot + Spring AI + 阿里云 GraphKit）改造而成。
> 业务场景：**电商经营数据问答**，面向「店铺运营」与「客服坐席」两类角色。

## 2. 模块划分

| 模块 | 说明 | 关键类 |
|------|------|--------|
| 编排/图 | 定义节点、边、状态 key、负责人机确认 | `GraphConfiguration`, `DataAgentSpec` |
| 召回 | 问题改写、证据召回、表/列 schema 召回、表关系 | `EvidenceRecallNode`, `SchemeReCallNode`, `TableRelationNode`, `SqlGeneratorNode` |
| 规划 | 可行性评估、拆解步骤计划、人工确认 | `FeasibilityAssessmentNode`, `PlannerNode`, `HumanFeedbackNode`, `PlanExecuteNode` |
| 执行 | SQL 生成/执行、Python 分析、报告生成 | `SqlExecuteNode`, `PythonExecuteNode`, `ReportGeneratorNode` |
| 安全 | 只读 SQL 校验、角色/店铺/单买家权限、敏感脱敏 | `security.SqlSecurityValidator`, `security.PermissionInterceptor` |
| 追踪 | 节点级 trace，输出火焰图与调用树 | `trace.TaskTraceService`, `TraceController`, `TracedNodeAction` |
| 数据管理 | 订单/商品/库存/退款 CRUD（写演示库） | `mall.controller.*`, `MallDataSourceConfig` |
| 知识库 | 预分模块的知识管理（问答示例/词表/口径/权限/运营） | `kb.KnowledgeBaseController`, `KnowledgeConfig` |
| schema入库 | 启动时把演示库表/列/外键写入 PG 并向量化 | `dataset.scheme.EcommerceSchemaInitializer` |
| 集成 | A2A(JSON-RPC) 对接上层，可作子 Agent | `integration.a2a.A2AController`, `GraphAgentExecutor` |

## 3. 数据流（一次问答）

1. 用户输入 → A2A `message/send`（带 `databaseId=ecommerce_ops`、角色 `role`）。
2. 证据 + schema 召回（pgvector 命中表/列/词表/问答示例）。
3. 可行性评估 → 规划器生成多步计划 → `HUMAN_FEEDBACK` 中断等待确认（复杂问题）。
4. 确认后逐步骤执行：`SQL_GENERATE → SQL_EXECUTE`（先过 `SqlSecurityValidator`，结果做权限脱敏）。
5. `REPORT_GENERATOR` 汇总为文本/表格报告流式返回。
6. 全程每个节点记录 `startMs/durationMs/status/parentId` 到 trace，供「调试管理」页展示火焰图与调用树。

## 4. 关键设计点

- **只读安全**：SQL 生成后、执行前强制校验，仅允许 SELECT，禁止 DROP/ALTER/DELETE/TRUNCATE/多语句。
- **权限隔离**：运营仅所属店铺；客服仅单买家；手机号/收货地址脱敏（在 `SqlExecuteNode` 中对结果集 mask）。
- **HITL**：复杂问题在人工确认节点暂停，由前端「提交人工输入」续跑（原应用特性）。
- **多轮上下文**：`MULTI_TURN_CONTEXT` 状态保留筛选条件，切换问题按需继承/重置。
- **可观测**：`TaskTraceService` 内存记录每次任务节点执行，产出调用树与火焰图数据。
