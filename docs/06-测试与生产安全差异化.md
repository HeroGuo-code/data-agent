# 测试 与 生产 环境差异化安全配置

## 6.1 差异对比

| 项 | 测试环境 | 生产环境(强制) |
|----|----------|----------------|
| 数据源 | SQLite 演示库 ecommerce_ops | MySQL 只读账号 / 数据中台 API |
| SQL 权限 | 允许本库读写(演示) | 只读账号，仅 SELECT |
| 敏感脱敏 | 已启用 | 已启用 + 审计 |
| 越权拦截 | 已启用 | 已启用 + 记录操作日志 |
| 全表扫描 | 不限制 | 强制 WHERE/limit，超阈值拦截 |
| 限流 | 关闭 | 高频大统计限流 + 超时兜底话术 |
| 埋点日志 | 仅控制台 | 结构化：操作人/提问/查询语句/耗时/结果条数 |
| 知识库 | 本地 sqlite kb_items | PG + 向量 + 权限管理 |

## 6.2 生产增强建议

1. **数据权限**：在 `PermissionInterceptor` 绑定登录态(operationId)，运营强制追加 `shop_id`。
2. **审计**：在 `SqlExecuteNode` 记录 `{operator, question, sql, durationMs, rowCount, status}` 到审计表。
3. **限流**：为 `/api/*` 增加令牌桶（如 Resillience4j / RateLimiter）。
4. **降级**：DB 异常统一返回「系统繁忙，请稍后再试」标准化兜底话术。
5. **联邦查询**：客服单买家查询强制传入 buyer_id，配合索引防批量扫描。
6. **Key 管理**：模型 api-key、数据库口令使用 KMS/环境变量，禁止硬编码(见 application.yml profile)。
