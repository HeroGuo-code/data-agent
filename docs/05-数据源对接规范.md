# 数据源对接规范（MySQL / 数据中台 API）

> 演示环境默认使用 SQLite 演示库（`ecommerce_ops`）。
> 生产环境按本规范将数据源替换为受控 MySQL 或封装好的数据中台 API。

## 5.1 统一数据源入口

工程通过 `SchemaDataSourceProvider` 抽象数据源，目前实现 `SqliteSchemaDataSourceProvider`（演示）。
生产建议新增 `MySqlSchemaDataSourceProvider` / `DataPlatformApiProvider`，并按 `databaseId` 路由。

\`\`\`java
public interface SchemaDataSourceProvider {
    javax.sql.DataSource get(String databaseId);
}

@Component
public class MySqlSchemaDataSourceProvider implements SchemaDataSourceProvider {
    // 从配置中心按 databaseId 取只读连接(账户无 DML 权限)
    public DataSource get(String databaseId) { ... }
}
\`\`\`

## 5.2 MySQL 接入要求

- 使用**只读账号**：`GRANT SELECT`，禁止 DML 与 `SHOW`/`EXPLAIN` 之外的权限。
- 连接串使用 `useSSL=true`、`serverTimezone=Asia/Shanghai`、`characterEncoding=utf8mb4`。
- 表/列描述需同步到 `db_table`/`db_column`（可后台扫描 information_schema 生成中文 description 后入库+向量化）。
- 生成 SQL 方言按库切换：`new-sql-generate.st` 的 `{dialect}` 参数（当前 sqlite，切 MySQL 用 mysql）。

## 5.3 数据中台 API（优先调用封装 API）

规范约定：优先调用已封装的业务数据 API；无 API 场景才生成只读 SQL。

\`\`\`json
// 约定响应结构
{ "code": 0, "message": "ok",
  "data": { "columns": ["shop_name","gmv","order_count"],
            "rows": [ ["旗舰店", 123456.0, 1024] ],
            "total": 1 } }
\`\`\`

- API 需透传鉴权 token，接口层统一做限流与超时兜底。
- API 未覆盖的查询才回退到 MySQL 只读 SQL，且同样过 `SqlSecurityValidator`。

## 5.4 指标口径字典（进入 glossary_knowledge 后被召回）

| 指标 | 口径 SQL 说明 |
|------|----------------|
| GMV/销售额 | SUM(pay_amount) WHERE status IN ('已完成','待发货') 剔除退款 |
| 客单价 | GMV / COUNT(支付订单) |
| 退款率 | SUM(refund.amount) / GMV |
| 转换率 | 支付订单数 / 访客数（流量表缺失仅订单侧口径） |
